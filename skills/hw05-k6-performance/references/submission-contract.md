# Portable Submission Contract

Read this reference during scaffolding and final validation.

## Expected evidence classes

- Assignment traceability and source/runtime discovery.
- Human-reviewed workload, data, correlation, checks, metrics, and safety design.
- Thin attributable scenario entries calling one shared business workflow.
- Public non-secret data and private credential templates/contracts.
- Separate Pilot and official run trees with `raw/`, `report/`, `logs/`, and
  `evidence/` where required.
- Reproducible analysis tied to native raw data and distinct real report views.
- Human review matrix contrasting original AI output with corrections.
- Continuous-testing proposal, Agent Skill, AI Audit, critique, Git log, main
  report, and required visual/video links.

## Final validation

Classify each requirement as `PASS`, `FAIL`, `MANUAL VERIFICATION REQUIRED`, or
`NOT APPLICABLE`. Never convert an absent human item to `PASS`. Verify filenames,
full raw artifacts, report directories, visual evidence, secret absence, Git
history, PDFs, URLs, grade format, and ZIP contents/checksum. Preserve k6-native
data honestly; never rename it to JMeter JTL.
